# 坐姿重复身体底稿修复 · 2026-11-02

## 原因与范围

仅处理 `main` 工程及编辑器的朝向归属判断，没有修改头发、服装、其他工程或既有未提交改动。

旧版切换朝向时允许继续选中另一个朝向的可编辑层；同素材表内复制也未检查朝向分组。坐姿正面 body（索引 221，父组 down）因此多出侧面键 `10_0_0`，含 5 个不透明像素；侧面 body（索引 226，父组 side）多出正面键 `10_1_0`，完全透明。列表只要看到当前朝向的键就显示该层，空白键同样导致重复条目。

## 本次修复

- `js/core.js`：共享朝向归属判断；合成、导出及换装使用的渲染层序排除其他朝向分组。
- `js/workbench.js`：列表过滤按朝向分组，不再让上个朝向的选中状态绕过检查；优先选中对应朝向同名层。
- `js/frame-tools.js`：复制、粘贴、批量复制按目标朝向匹配；显式指定其他朝向图层时拒绝。
- 主工程只删除上述两条错误帧键，不删除任何图层。以带 If-Match 的 PUT 保存并 GET 回读，其他 JSON 数据逐项相等。

`changes.patch` 是相对本次开始时工作区的差异，不是相对 Git HEAD 的全部既有改动。`before/`、`main-before.json`、`sha256.json` 保留本次原件及前后 SHA256。

## 恢复方法

1. 先导出前台尚未保存的工程副本，不强制刷新或覆盖草稿。
2. 代码恢复前对照 `sha256.json` 的 after 值；若当前文件已发生其他修改，不整文件覆盖，应只反向应用 `changes.patch` 中本次修改。若未发生其他修改，可将 `before/` 中三个文件复制回原来的 `js/` 路径。
3. 工程通过 `GET /api/project?id=main` 读取当前 ETag；若仍等于 `main-after.json`，可将 `main-before.json` 作为请求体，带 `X-Pixel-Editor: 1`、`Content-Type: application/json`、当前 `If-Match` 执行 PUT。若工程已有新改动，只按原图层和父组身份补回上述两个键，禁止用旧整稿覆盖新修改。409 时停止并比较。
4. 回读并核对后再让用户刷新页面加载相应代码。

本次未对用户实际页面执行保存、刷新、恢复备份或清空浏览器草稿。旧页面需重新加载才使用新代码；如有草稿，先导出副本，不能直接刷新。修复写入产生了新 ETag，旧草稿直接保存可能提示版本冲突，这是保护新旧修改而非本次重复底稿问题。
