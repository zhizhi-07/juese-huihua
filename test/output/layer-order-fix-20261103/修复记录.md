# 正面后发与层级箭头修复

## 原因与改动

- 卡片改名原来不调用 `app.renameLayer`，因此新层写“后发”只是换名字；原属前发的层写“正面后发”还会继续保留前发类别。现在首次识别和明确换类型复用原有归位、撤销逻辑。同类型款式改名不重排。
- 箭头原来按完整工程数组换相邻层，可能只换过其他画布、其他方向或隐藏的图层。现在跳过这些非当前绘制对象；组边界点击不再只脱组而不改变遮挡。
- 自动归位时原来用其他画布的发饰等作参照，可能把本画布的前发放到头部下面。现在只比较目标画布。
- 更新两个脚本的版本参数。没有改头发、脸部像素或任何工程 JSON，没有刷新用户页面。

## 验证

`node test/layer-controls.cjs --before`：退出 1，修复前五项回归均失败；原始输出见 `baseline.log`。

`node test/layer-controls.cjs`：退出 0；验证新层命名、前发改后发、跨画布和方向的箭头、跨组移动、画布与 PNG 的实际重叠像素、撤销/重做，以及保存重开后的层序与像素保留。输出见 `after.log`。

12 个测试脚本全部退出 0，见 `regression.log`。包括原有后发正背面遮挡、眼睛与前发顺序、方向隔离、头发动画、图层复制合并、成品、保存冲突保护。

旧 `hair-slots.cjs` 的模拟图层缺少当前导出器需要的 `frameData`，修复前代码也会报同一个 TypeError；记录见 `hair-slots-existing-fixture-error.log`。仅为该测试补齐 Map，未因此修改生产导出器。

未在用户当前标签页操作或验证；原有背面后发覆盖后脑的特殊规则保持不变。本次箭头像素验证针对用户报告的正面遮挡。
