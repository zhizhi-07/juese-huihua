# 头发素材混搭与像素化流程

适用：把用户已有的 TV / Variation 发型素材，做成当前人物工程可独立换搭的前发、后发。**以后此类任务按本流程做；不需要生图，不重新发明发型。** 新的用户要求优先；这份流程不是修改其他工程或其他动作的授权。

本次实例：前发80011＋后发80009，人物分支 `character-gold-mix-1793320553623`，先做待机。先读《后台工程读写约定.md》及《人物绘制AI要求与自检.md》。不要顺手修改编辑器程序。

## 2. 定工程，先备份，不动别人的稿

1. 确认是用户分配的人物工程；不要建成“只有头发”的工程，也不要改主工程试效果。
2. GET对应 `/api/project?id=编号`，保留原始JSON、ETag和SHA256，在副本上处理。
3. 查看当前身体、头部、手和目标待机所有帧；当前画面可能有未保存草稿，API拿不到时须如实说明，不能强刷网页。
4. 只增加或修改本次前后发，不搬入整套旧衣服、旧眼睛或被否决发型。现有其他像素、图层关系、显隐、时长和其他动作保持不变。

## 3. 裁选、抠图和翻转

1. 有透明TV原图就先用原图，避免从带标记、红框的截图取素材。按3×4格裁选后再细调边界，发尾和顶部弧线都要留全。
2. PNG中 **alpha=0 的RGB即使有黄色、白色或黑色，也仍是透明**。读写、取色、缩放都必须尊重alpha，不能把隐藏的RGB当底色补出来。本次原图确实含有这样的透明RGB。
3. Variation中的灰黑人形确实不透明：先在源尺寸下“去黑色人形”，或“从原图取色＋按颜色抠图”；检查“只抠灰黑”，调整容差。不要把金色头发的深棕描边一起抠没。
4. 检查耳侧、卷尾内部、弧形边缘是否被误删。误删就回到抠图前改选色/容差或局部修，不用自动膨胀把整圈轮廓撑粗。
5. 源图朝向与目标相反时，**前发和后发一起水平翻转**，不要只翻一件。判断“朝左/朝右”按人物脸，不按马尾伸出方向。上下翻转只在用户需要时使用，不能拿它替代转向。
6. 裁选框可移出源图边界，外部作为透明留白；必须仍与源图相交。留白不等于发尾被删掉。真正导入的输出尺寸仍须放得进目标帧。

## 4. 缩放：保持发型，不让算法重新设计

- **原生像素素材**：选“最近邻（保留像素形状）”，先保留原色；少做一次非整数缩放就少一次轮廓损失。变更尺寸后逐像素检查，不在各方向随意使用不同缩放比例。
- **高清参考或用户不想像素化的部件**：用“原图缩放（不做像素化）”，按需要保留原色与透明度；这条分支不是强制三色化或硬像素化。它适用于用户明确要原图处理的眼睛等部件，不代表可以擅自修改眼睛。
- “适合当前画布”只保证放得下，**不保证贴合头部**。带透明边距的整张图不能直接按画布宽度放大；要以实际头部定位。
- “保细线轮廓”默认关闭；它可能变粗、串色、填掉发束间隙。不能靠开这个选项替代手修缺掉的弧线。
- 算法只做初稿。源图已有完整发型，不能把它转成另一顶帽子、把卷尾压成灰色疙瘩，或用整层反复拉伸补比例。

## 5. 对齐：以素体头部为准，不以素材框为准

先为每个方向记录头顶、脸中轴、额边、耳侧及发尾位置，再导入。先完成一帧和三方向静态检查；未获认可的试稿不自动扩展到其他动作。

本次36×36待机的实测标尺（坐标从0开始，只作为本例，不是所有人物的固定值）：

- 头顶Y依帧为 `[4,4,6,6]`；发顶与对应素体头顶齐平，不另往上抬。
- 人物对称轴X=17.5，镜像对应 `X'=35-X`；不是照旧32画布的中轴直接画。
- 正、侧面的主刘海深度约9像素，前两帧末端Y=13，后两帧Y=15。这里测的是额前主刘海，不包含更长的鬓发。
- 正、侧面使用同一把垂直标尺；不能正面短、侧面突然长一截。近远鬓发透视不同，但主刘海长度须对应。
- 不拉伸头部、手或身体去迁就头发。画布扩边也只是加透明边，不是把人物等比放大。

以后工程尺寸或头部有变化，重新测量以上值。不要看到这份文档就再次扩全库画布。

## 6. 配色和光影：简单、相连、前后统一

头发用当前规则三色：描边 `#777777`、暗部 `#B2B2B2`、底色 `#D1D1D1`；硬像素头发只用全透明/全不透明，不加抗锯齿和额外高光。

处理顺序：先分清浅色发帽、内侧暗部和真正的外轮廓，再映射三色；最后人工合并破碎色块。**不要只按每个像素亮度机械分级就交付。**

- 顶部用完整浅灰块，下面用一两块相连暗灰表现转折。保留原发型的扎发、卷曲结构，不靠撒零散深浅点表现发丝。
- 以前能用的平滑弧线、成组暗部可以继续用；不把过去被否决整稿恢复回来。
- 深灰主要用于外轮廓、贴脸边、发束必要的遮挡处，不把所有色块边界描成深线。
- 背面不能为了“简单”把马尾连接全部抹平。须看得出后脑收向扎点，再延伸出卷尾，而不是头盔两边粘两块翅膀。

## 7. 混搭接缝：不是两块素材拼完就算完成

本次红框问题：侧面前发左侧的深灰边，在已有后发发帽上形成了长直竖缝，看起来像两片硬板。

**先区分内部接缝和外轮廓，再处理：**

1. 分别单看前发、后发，再看叠加；确认竖线是两件相交后的内部边，不是脸边、耳缘或真正发际线。
2. 相交部分的浅灰发帽要能接成连续色块；遮挡线只在需要的发束转折处短暂出现，不沿整条接口机械描边。
3. 在交叠处把多余深线并入相邻底色；下段用短的阶梯暗块过渡到鬓发，避免“一条直线从头顶插到耳朵”。**这是逐像素改色，不是模糊、加渐变或加粗描边。**
4. 不简单擦出透明缝；前发自身的发帽、刘海、鬓发仍要有完整像素，后发自身的后脑和扎点也要完整。不能两件互相依赖补洞。
5. 扎点处保留必要深线，脸边和外侧轮廓保持一像素收口。不是把全层所有深灰一键换成浅灰。
6. 同样的修整跟随该方向全部待机帧；不要只改第1帧，让播放时竖缝闪回。
7. 用相同背景比较前后，避免浅/深底差异误导对光影的判断；再分别在浅底、深底检查。

![侧面前后发内部接缝：修改前与修改后，同背景](教程配图/头发素材流程/03-侧面接缝前后.png)

上图本次只改每帧18个内部颜色像素，四帧跟头部位置同步；没有擦掉透明轮廓，也没有改正面、背面或身体。不是以后每款都照抄18个坐标，应先定位各自真正的交叠边。

## 8. 分层和显示顺序

- 槽位仍是**前发、后发、饰品**。RearHair1和RearHair2归同一个后发款式，按方向提供像素；左右卷尾也归后发，不增加第四个“马尾槽”。
- 正面：后发在头身后，前发在头前。侧面按真实遮挡组合；本例有同一后发组下的侧面子层，用于耳侧及连接位置，不意味着整块后脑都移到脸前。
- 背面：后发盖住后脑，前发数据全透明；仅隐藏前发不算合格。后发不能包含当前特定刘海的脸部开口。
- 渲染、缩略图、播放和PNG导出统一使用 `PE.getRenderLayers`，不能测试脚本按数组顺序画一张、前台却用另一套顺序。
- 独立开关前发/后发检查，另在测试副本做交叉混搭；不要为演示把旧素材塞进用户当前分支。

## 9. 动画：参考源图，但按当前素体手工取帧

1. 三列原图都要看，用于理解卷尾如何摆、扎点在哪里；不是只取中间一格后，把整顶头发平移四次。
2. 源图3格不等于当前待机4帧，不能原样塞入改变角色动作。保留当前身体呼吸和帧时长，只让头发跟随。
3. 发根跟随每帧头部；本例头下沉2像素，长发下段压缩一行，尾部总体约下移1像素。主刘海跟头顶标尺，不单独伸长。
4. 卷尾末端可有约1像素延迟；从连接处连续过渡，描边和暗部随同一束一起变，不能从某一行突然切断横移。
5. 正、背面对称款仍绕人物中轴对称；侧面另按近远关系处理。不要为了凑四张不同图乱摆发根；两帧同姿态允许相同上半部分。
6. 看完整循环 `1→2→3→4→1`，重点看接缝是否闪、卷尾是否断、根部是否漂、最后回第一帧是否突跳。

## 10. 检查和保存，不能只看一张大图

- [ ] 来源、方向、前后发职责核对过；没有把黑色展示素体或透明RGB带入。
- [ ] 三方向、所有待机帧都生成了非空合成；原尺寸看整体，放大看一像素轮廓，浅深背景都看。
- [ ] 头顶齐平，正侧主刘海长度对应；弧线无缺口，内部无长直拼接线；扎点、卷尾仍能辨认。
- [ ] 单独前发/后发、合成及测试副本中的换搭均检查；背面前发全透明。五官/衣服未提供或未测时如实记录，不假称做过。
- [ ] 身体、手、其他图层、其他动作、原始动作备份、帧数时长、尺寸与层级未被无意修改。
- [ ] 动画循环检查完成；实际主画布render、预览合成和PNG导出一致，不拿两个透明画面相等充数。
- [ ] PUT保存带 `X-Pixel-Editor: 1` 和读取时ETag的 `If-Match`；409则比较新稿后再合并，禁止取新ETag强传旧整稿。
- [ ] 保存后GET实际API回读；保留前稿、像素差异、验证输出、预览和恢复办法。恢复也须防止覆盖后续保存。
- [ ] 不强制刷新有未保存草稿的用户页面；未做网页实测就明确写“未做”，不要把离屏检查称作浏览器检查。

**后续默认路线：认部位 → 选对方向 → 透明抠图 → 统一尺度 → 贴合素体 → 三色简明光影 → 手修接缝 → 独立分层 → 手工待机取帧 → 自检 → 版本校验保存。** 不加生图、复杂算法或其他动作，除非用户另有要求。
