# 前手置顶层级修复（2026-11-08）

## 问题

前手（`hand` 层，近身那只手）在图层数组里被放在「身体 / 衣服 / 头部 / 眼睛」所属的分组内，而衣服、前发、后发、饰品都是工程根层的独立图层（数组位置在分组之后）。绘制顺序按数组位置走，所以衣服、眼睛、头发会盖住前手。

## 改法（只改绘制顺序，不动任何工程数据）

1. `js/core.js`
   - 新增 `PE.isFrontHandLayer(layer)`：手部层里排除 `hand 2`（后手）后剩下的就是前手。
   - `PE.getRenderLayers()` 在原有的「后发盖过头身 / 背面饰品置顶」处理之后，再把当前规格的前手层整体提到绘制顺序末尾（最前）。原来的提前 `return` 分支改成统一出口，避免漏掉置顶。
   - 后手（`hand 2`）顺序完全不变，仍然留在身体后面。
2. `js/wardrobe.js`
   - `PE.Wardrobe.rank()` 里前手从 15/22 提到 99，保证「成品衣柜 / 换装测试」的试穿合成与主画布一致；后手（身体之前的那一只）仍是 -10。

因为只改渲染顺序，所以：

- 图层数组、父级、索引、像素、显隐、锁定、命名一个都没动，不需要通过 API 保存工程。
- 以后新加的衣服或头发（哪怕追加到数组末尾、排在前手后面）也不会再压住前手。

## 验证

- 新测试 `test/front-hand-top.cjs`：正面/背面两种方向，衣服、眼睛、前发、饰品与前手重叠时最后合成出来的一定是前手颜色；后手仍在身体后面；主画布、手部预览开关、PNG 导出三条路径一致；追加的新衣服层压不住前手。
- 只读审计 `scripts/front-hand-order-audit-20261108.cjs`：用备份的旧顺序函数与新顺序逐帧对照。
  - `data/shared-project.json`：66 帧，30 帧合成变化，155 个前手像素从被衣服/眼睛/头发盖住变成可见，前手像素被盖住数 0/948。
  - `data/projects/draft-conflict-1793762650078-819fdffe.json`（当前草稿）：66 帧，16 帧合成变化，39 个前手像素回到最前，被盖住数 0/950。
  - 对照图：`output/front-hand-order-20261108/*-before-after.png`；报告：`*-report.json`。
- 回归：`front-hand-top`、`hair-slots`、`eye-layer-order`、`directional-base`、`layer-shortcuts`、`part-export`、`hands`、`regression`、`native16-clean`、`eye-sync`、`hair-animation`、`hair-avoid`、`poses`、`timeline`、`project-branches`、`character-sync`、`visual-layers`、`frame-copy` 全部 PASS。
- 修改前就存在的失败（与本次无关，改前改后一致）：`layer-order`、`layer-controls`、`wardrobe`、`cross-action-copy`、`hair-demo-parity`、`wardrobe-rear-order`（需要参数）。
