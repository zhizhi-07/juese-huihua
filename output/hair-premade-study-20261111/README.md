# 原版预设头发研究（2026-11-11）

## 结论
应采用离散像素姿态复用，不应把发梢滞后/正弦飘动作为默认算法。原文件是手绘帧，不能从帧反推出作者使用了某种程序算法。

直接读取用户指定 Premade Character 的八个 aseprite；共分析882个方向帧。Farmer、Florist、Inn Keeper、Merchant有独立hair层；其他四个只对acc配饰层作辅助统计，不把帽子/配饰统计混称头发统计。Inn Keeper正面头部层实际叫Layer 2。

四款hair的待机/行走/拾取共216帧：189帧可以与本方向待机四帧中的某一帧逐RGBA像素一致地整块平移匹配。去掉待机自身后，行走/拾取168帧中141帧匹配，27帧是例外。匹配是观察到的图形复用，不证明制作过程。

|角色|基本三动作帧|匹配待机形态|例外|
|---|---:|---:|---:|
|Farmer|54|49|5|
|Florist|54|48|6|
|Inn Keeper|54|43|11|
|Merchant|54|49|5|

Farmer/Florist的三个方向，忽略整块位置后：
- 待机形态为 A B B A。
- 正面、背面行走为 B B A A B B A A。
- 侧面行走前半为 B B A，随后四帧有另外的轮廓，最后回A，不可直接用同一块平移覆盖。
- 正面拾取为 A B B B A A；侧/背有少量例外。
- Merchant背面待机第三帧与B还有颜色/像素差异；Inn Keeper更多帧有微小修整，不能强称所有发型只有两张。

## 压短不是简单删一行
Florist正面待机首帧hair包围盒(33,25)-(45,37)，次帧(33,25)-(45,36)：高度13变12，但头顶肩角、发梢和描边也改变。背面两帧包围盒均为13×13，轮廓仍变化。脚本另穷举删除一整行并平移，不能精确复现这些变化。因此不能将原版归纳为“所有帧只删一行”，也不能据此对任意用户发型自动裁一行。

## 对当前实现的定位与建议（尚未修改）
js/hair-animation.js的refresh中，nativeTips路径按当前头部偏移减上一帧偏移，夹到±1，再交给deform；这是速度驱动的局部发梢滞后，不是上述离散图形复用。把幅度缩小仍不是用户所要的简单规则。

最小正确方向：每个方向保留原始发型；头发整体按实际头部锚点移动；需要原版压短观感时，使用明确的A/B像素形态及动作阶段表，不以速度/时间/正弦产生发梢变化。侧面另一轮廓、拾取低头等例外独立标注，不能强拉同一图。A/B怎样从用户单张首帧安全生成，尚未验证，不能称已解决。坐姿不在这套预设tag中，没有坐姿证据，不新增正/背坐姿。

## 产物与复核
- analyze.cjs：只读原版，复用现有js/aseprite.js和scripts/png.cjs，无新依赖。
- report.json：原文件路径及SHA256、每方向/动作/帧的头部包围盒偏移、平移像素差、最佳删行差、待机形态匹配。
- summary.json：各角色统计；其中acc是配饰，不能当纯头发。
- 八张角色名PNG：每张九行，依次正面待机/行走/拾取、侧面三动作、背面三动作。仅合成head+hair或head+acc，不是完整人物，透明下方的零散像素可能来自head层。
- example.png：Florist正面待机与侧面行走节选；上排4帧、下排8帧。
- run.log：成功执行原始输出。命令：`node output/hair-premade-study-20261111/analyze.cjs`，退出0。
- 自检：八源文件读前读后SHA256一致；输出PNG回读尺寸断言通过，report共八项。已目检Florist和Inn Keeper逐帧图。

没有修改任何原素材、编辑器源码、工程JSON；没有API写入，没有前台刷新。分析不需要恢复脚本。首次检查发现并修正了“全部都有hair/head层”的错误假设；没有用空层补造头发证据。部分扩展动作头部为空时报告headOffset=null，不用假锚点计入精确跟头。
